# Contributing to OpenCADIrrigation

Issues and pull requests are welcome on [GitHub](https://github.com/videjunior/opencadirrigation). Contributions are
accepted under the [MIT licence](LICENSE.md) of the project. Please keep to the [code of conduct](CODE_OF_CONDUCT.md),
and report security problems privately ([SECURITY.md](SECURITY.md)). Portuguese:
[docs/manual/pt-BR/development.md](docs/manual/pt-BR/development.md) explains the development in Portuguese.

## Before a pull request

- Run `dart analyze lib test tool bin` (no issue at all) and `flutter test`. The repository is formatted 200 columns
  wide: plain `dart format <files>` keeps it.
- Rebuild `web/design_worker.js` with `tool/build_worker.sh` after changing `lib/core` or the string table, and run
  the generator a failing guard test names (site pages, examples, catalogues, the AI tools table…).
- Every fixed defect gets a test that fails without the fix.
- The development setup, the commands and the test map are in [docs/manual/development.md](docs/manual/development.md).

## What goes where

- **Catalogues**: follow [catalogs/README.md](catalogs/README.md), run `dart run tool/gen_catalogs.dart` and open a
  pull request; the tests guarantee unique ids and plausible curves.
- **Examples**: add a builder in `lib/app/examples.dart`, texts in the string table and run
  `dart run tool/gen_examples.dart`; the test designs the example and requires zones inside the window.
- **Engine**: every new formula comes with a test against a published reference value.
- **Interface**: colours come from `Cad.*` (`lib/app/theme.dart`), which change with the theme: read them in `build`
  and `paint`, never in `const` expressions or in fields that outlive a rebuild. Visible texts go through the string
  table. A new command, tool, menu item or dialog needs its route for the AI assistant in
  `lib/app/ai/ai_coverage.dart` (the coverage test says which is missing).
- **Site**: the pages, their manifests, the legal pages, `site.js` and the hosting configuration are generated by
  `dart run tool/gen_site.dart` from `tool/site.dart` and `tool/site/` (see [hosting/README.md](hosting/README.md)).

## Translations

- Every key of the string table (`lib/app/i18n.dart` and its parts in `lib/app/i18n_parts/`) is a (pt, en, es)
  tuple; every other language is a pack in `assets/i18n/<code>.json` (strings, tutorial and catalogue names, the last
  two keyed by the English text). The tests fail on a missing key or placeholder.
- [tool/i18n/glossary.json](tool/i18n/glossary.json) lists the keys that read the same in every language (names,
  symbols, formulas), those a pack may leave in English, the ones waiting for a translation, and one name per concept
  in each language; `test/core/i18n_glossary_test.dart` fails on an English label in a non-Latin script, on more
  English labels in a Latin-script pack and on an avoided word.
- Native speakers review a language in a spreadsheet with `dart run tool/i18n_review.dart export <code>` and
  `import <file>` ([how](docs/manual/languages-and-site.md#native-speaker-review-of-the-translations)).
- The site pages are in `tool/site.dart` (pt, en, es) and `tool/site/<code>.dart`; the legal pages in
  `tool/site/legal.dart`.
- A string with characters the PDF fonts do not cover yet needs `tool/fonts/build_fonts.py`.
- Documentation is written in English (`README.md`, `docs/manual/`, `docs/TECHNICAL_STUDY.md`, `docs/API.md`) and
  translated to Portuguese (`README.pt-BR.md`, `docs/manual/pt-BR/`, `docs/PESQUISA.pt-BR.md`, `docs/API.pt-BR.md`):
  change the English version first. The snippets of the API documents are run by `test/core/api_examples_test.dart`.

## Editorial rule

Competing irrigation-design products and their makers are never named, anywhere in the repository (code, comments,
texts, tests, documentation and commit messages), and neither are CAD products: a file format goes by the name of the
format (DXF, DWG R2000). Component manufacturers appear only as the origin of catalogue data; EPANET may be cited as
the reference of an algorithm; data and map providers (OpenStreetMap, Esri, Open-Meteo…) and the AI providers
(Anthropic, OpenAI) appear as sources and credits; other programs (spreadsheets, GIS, virtual globes, browsers) only as
the target of a file format. `test/editorial_names_test.dart` checks the forbidden names by their SHA-256, so it names
none of them.

## Releasing

1. Bump `version:` in `pubspec.yaml` and run `dart run tool/gen_version.dart`.
2. Add the section of the version to [CHANGELOG.md](CHANGELOG.md) and [CHANGELOG.pt-BR.md](CHANGELOG.pt-BR.md), and
   set `version` and `date-released` in [CITATION.cff](CITATION.cff) (a test checks both).
3. Read the known limitations ([docs/manual/limitations.md](docs/manual/limitations.md)) and the statements about
   storage and privacy ([docs/manual/privacy-and-network.md](docs/manual/privacy-and-network.md), the privacy policy
   in `tool/site/legal.dart`) again whenever a behaviour changed; keep the counts approximate ("about 1,900 tests").
4. Update Help → About in the 20 languages when it names the version's features, set `siteLastMod` in
   `tool/site.dart` and run `dart run tool/gen_site.dart`.
5. Commit, build with `sh tool/build_web.sh`, apply `hosting/firebase.json` and deploy (see
   [hosting/README.md](hosting/README.md)), check the live site, then tag `vX.Y.Z`, publish a GitHub Release with the
   changelog section and run `dart run tool/indexnow.dart`.
